### Probes

`/healthz` is liveness: 200 as long as the process serves HTTP. `/readyz` runs every
registered `health.Checker` in parallel (timeout `health.timeout` each) and returns 200
when all are up, 503 otherwise:

```json
{"status": "up", "checks": [
  {"name": "postgres", "status": "up", "latency_ms": 2}
]}
```

A new dependency implements `Name() string` and `Check(ctx) error` and is added to the
registry in `internal/di.provideHealth` (`health.WithChecker`).

## Configuration

`configs/config.yaml` holds every key. Each key is overridden by
`{{ cookiecutter.env_prefix }}_<PATH>` (upper case, `.` → `_`), e.g. `log.level` → `{{ cookiecutter.env_prefix }}_LOG_LEVEL`.
`{{ cookiecutter.env_prefix }}_CONFIG` selects another file. The image defaults to `env=prod`, JSON logs
at info level{% if cookiecutter.use_postgres == 'y' %} and no auto-migrate (the deploy sets it per stack){% endif %}.

`http.request_timeout` puts a deadline on every request context; it reaches the
queries through `ctx` and an expired request answers 504.

## Database

Postgres through a pgx pool (`internal/postgres`, functional options), sqlc for the
queries and goose for the migrations:

| Path | |
|---|---|
| `db/migrations/*.sql` | goose migrations, embedded in the binary. `00001_init.sql` creates the schema `{{ cookiecutter.db_schema }}` |
| `db/queries/<table>.sql` | sqlc queries, one file per table; `meta.sql` backs the readiness check |
| `internal/db/sqlc` | generated by `task sqlc`, never edited |
| `db/seed/*.sql` | idempotent local data, `task db:seed` |

Everything lives in the schema `{{ cookiecutter.db_schema }}` (tables and `goose_db_version`): it is the
`search_path` of every connection, so queries and migrations do not qualify names.

Connection settings are discrete keys (`db.host`, `db.port`, `db.user`, `db.password`,
`db.name`, `db.sslmode`); the pool is `db.pool.*` and the timeouts `db.timeouts.*`:

| Key | Default | |
|---|---|---|
| `db.timeouts.connect` | 5s | dial of a new connection |
| `db.timeouts.startup_ping` | 5s | connectivity check at startup |
| `db.timeouts.query` | 10s | default deadline of each query (also inside transactions) unless `ctx` ends sooner |
| `db.pool.max_conns` / `min_conns` | 5 / 0 | keep `min_conns` 0 with scale to zero |
| `db.pool.max_conn_lifetime` (+ `_jitter`) / `max_conn_idle_time` | 30m (5m) / 5m | |

The sqlc methods take the DBTX (`emit_methods_with_db_argument`): pass `db.DBTX()`,
or the transaction given by `db.InTx`, which commits on `nil` and rolls back on error
or panic:

```go
q := sqlc.New()
item, err := q.GetItem(ctx, db.DBTX(), id)

err = db.InTx(ctx, pgx.TxOptions{}, func(tx sqlc.DBTX) error {
	if _, err := q.CreateItem(ctx, tx, a); err != nil {
		return err // rollback
	}
	_, err := q.CreateItem(ctx, tx, b)
	return err // nil: commit
})
```

### Migrations

`db.auto_migrate: true` applies pending migrations at startup. Every run (startup or
task) holds a Postgres advisory lock, so instances starting together do not race.
With `auto_migrate: false` run them yourself, locally or from a CI job:

```sh
task migrate:create -- add_orders     # new db/migrations/000NN_add_orders.sql
task migrate:up                       # local database (configs/config.yaml + .env)
cp .env.prod.example .env.staging     # fill in host, user, password, ...
task migrate:status ENV=staging       # loads .env.staging (git-ignored)
task migrate:up ENV=staging
task migrate:down ENV=staging         # asks for confirmation
```

In CI export the same `{{ cookiecutter.env_prefix }}_DB_*` variables and run `task migrate:up`.

## Authentication
{%- if cookiecutter.use_auth == 'y' %}

Two layers:

1. **Cloud Run IAM** admits the caller: the service accounts in `access.callers`
   (`deploy/config/<stack>/config.yaml`) get `roles/run.invoker`. A caller (an API
   gateway, another service) sends its own Google ID token in
   `X-Serverless-Authorization`, which Cloud Run checks and strips, and forwards the
   user's `Authorization` header unchanged. With
   `access.public: true`, allUsers get the role instead and layer 2 is the only gate.
2. **The app** verifies the end user's `Authorization: Bearer <JWT>` on every route under
   `{{ cookiecutter.base_path }}/v*` except `{{ cookiecutter.base_path }}/v*/public/...`; `/healthz` and `/readyz`
   stay open. Failures answer 401 (`WWW-Authenticate: Bearer`, the reason is only in
   the logs), a missing role 403.

`auth.*` in `configs/config.yaml` (deploy: `app.auth`):

| Key | |
|---|---|
| `mode` | `jwks` (keys from `jwks.url`, cached, refreshed every `jwks.refresh_interval` and on an unknown `kid`) or `static` (PEM public key: `static.public_key`, or `static.public_key_file`) |
| `issuer`, `audiences` | `iss` must match, `aud` must contain one of them |
| `algorithms` | allowlist, default `[RS256]`; `none` and HS* are always rejected |
| `roles_claim` | dotted path of the roles: an array (Firebase custom claim `roles`) or an object whose keys are the roles (ZITADEL `urn:zitadel:iam:org:project:roles`) |
| `token_types` | optional `typ` allowlist, e.g. `[at+jwt]` for ZITADEL access tokens |
| `enabled` | `false` (env=dev only) logs every request in as `dev_principal` |

| IdP | `issuer` | `audiences` | `jwks.url` |
|---|---|---|---|
| Firebase / Identity Platform | `https://securetoken.google.com/<project>` | `[<project>]` | `https://www.googleapis.com/service_accounts/v1/jwk/securetoken@system.gserviceaccount.com` |
| ZITADEL | `https://<instance>.zitadel.cloud` | `[<project id>]` | `https://<instance>.zitadel.cloud/oauth/v2/keys` |

Firebase clients send their ID token, ZITADEL clients a JWT access token (set the
application's token type to JWT); both are accepted. In jwks mode `/readyz` has an
`auth_jwks` check, down until the keys are fetched once (startup never fails on it).

Handlers read the caller with `auth.FromContext(ctx)` (`Subject`, `Email`, `Roles`,
`Claims`); `middleware.RequireRole("admin")` restricts a route. `GET {{ cookiecutter.base_path }}/v1/me`
returns the caller.

Local development uses static mode with a dev key pair (`.dev/auth`, git-ignored):

```sh
task auth:keygen                                  # once (also run by task setup)
task auth:token SUB=alice ROLES=admin TTL=1h      # signed token for the local config
```

Tests sign tokens with `internal/auth/authtest` (`NewIssuer`, `Token`, `Verifier`, `JWKS`).
{%- else %}

None in the code. The Cloud Run service has no public binding: only the service
accounts in `access.callers` (`deploy/config/<stack>/config.yaml`) get
`roles/run.invoker`, and Cloud Run rejects every other request. Callers send a
Google ID token whose audience is the service URL:

```sh
TOKEN=$(gcloud auth print-identity-token \
  --impersonate-service-account=<caller>@{{ cookiecutter.gcp_project }}.iam.gserviceaccount.com \
  --audiences=<service url> --include-email)
curl -H "Authorization: Bearer $TOKEN" <service url>{{ cookiecutter.base_path }}/v1/items
```

From Go, `google.golang.org/api/idtoken.NewClient(ctx, "<service url>")` does the same.
{%- endif %}

## Releases and images

Commits follow Conventional Commits (pre-commit hook). On `main`, release-please
keeps a release PR open; merging it tags `vX.Y.Z`, updates `CHANGELOG.md` and
`deploy/config/default.yaml` (`image.tag`), and calls the `image` workflow, which
pushes `{{ cookiecutter.gcp_region }}-docker.pkg.dev/{{ cookiecutter.gcp_project }}/{{ cookiecutter.ar_repository }}/{{ cookiecutter.project_slug }}:<tag>` (+ `latest`).
Rebuild a tag by hand: `gh workflow run image.yml -f tag=v0.1.0`.

The workflow authenticates with Workload Identity Federation. Repository
variables (set by the template):

| Variable | Value |
|---|---|
| `GCP_PROJECT` | `{{ cookiecutter.gcp_project }}` |
| `GCP_REGION` | `{{ cookiecutter.gcp_region }}` |
| `AR_REPOSITORY` | `{{ cookiecutter.ar_repository }}` |
| `IMAGE_NAME` | `{{ cookiecutter.project_slug }}` |
| `WIF_PROVIDER` | `projects/<number>/locations/global/workloadIdentityPools/{{ cookiecutter.wif_pool }}/providers/github-{{ cookiecutter.project_slug }}` |
| `WIF_SERVICE_ACCOUNT` | `{{ cookiecutter.wif_service_account }}` |

The provider `github-{{ cookiecutter.project_slug }}` only accepts tokens of `{{ cookiecutter.github_owner }}/{{ cookiecutter.project_slug }}`;
the service account needs `roles/artifactregistry.writer` on the repository.

## Deploy (Pulumi)

`deploy/` is a separate Go module. Stack config: `deploy/config/default.yaml` +
`deploy/config/<stack>/config.yaml` + git-ignored `deploy/config/<stack>/secret.yaml`
(or `DEPLOY_SECRET_*` env vars).

```sh
gcloud auth application-default login
pulumi login gs://<state bucket>          # once
cp deploy/config/dev/secret.example.yaml deploy/config/dev/secret.yaml   # secrets{% if cookiecutter.use_postgres == 'y' %}: db_password{% endif %}{% if cookiecutter.use_redis == 'y' %}, redis_url{% endif %}
$EDITOR deploy/config/dev/config.yaml     # project, access.callers{% if cookiecutter.use_postgres == 'y' %}, app.db (host, user, name){% endif %}
cd deploy && pulumi stack init dev && cd ..
task deploy:check deploy:preview deploy:up STACK=dev
```

It creates: the runtime service account `<service>-run`{% if cookiecutter.use_postgres == 'y' or cookiecutter.use_redis == 'y' %}, Secret Manager secrets
({% if cookiecutter.use_postgres == 'y' %}`<service>-db-password`{% endif %}{% if cookiecutter.use_postgres == 'y' and cookiecutter.use_redis == 'y' %}, {% endif %}{% if cookiecutter.use_redis == 'y' %}`<service>-redis-url`{% endif %}) readable only by it{% endif %}, and the Cloud Run service
(min 0 instances, CPU only during requests, startup probe `/readyz`, liveness
`/healthz`) with `roles/run.invoker` for each caller{% if cookiecutter.use_auth == 'y' %} (and allUsers with
`access.public: true`). `app.auth` becomes `{{ cookiecutter.env_prefix }}_AUTH_*`; in static mode the public key
is the secret `auth_public_key` (Secret Manager `<service>-auth-public-key`){% endif %}.

